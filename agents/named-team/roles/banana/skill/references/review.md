# 独立レビューと指摘対応

[contracts.md](contracts.md) で確認したプロジェクトのレビュー経路を使う。
特定プラグイン・軽量モデル・別 provider を共通既定として強制しない。
利用不能や供給断で別モデルへ自動切替せず、未達を記録して承認された代替経路を確認する。

## レビューを渡す

実装・修正に未関与の担当に repo / PR / 固定 full head SHA と必要な一次資料を渡す。
承認済み AC、該当契約、実 diff、関連実装、検査・現在 SHA の CI、未解決コメントを読める状態にする。
実装者の説明だけを証拠にしない。情報不足は不足のまま示す。
金銭・権限・migration では、その影響と adversarial 観点を明示し、契約に合う独立レビューを受ける。

レビュー担当と実装担当の識別子、関与歴、model / effort の実効設定、対象 SHA、観測日時を残す。
判定の model 要件と、製品・運用判断の model 要件を混ぜない。
技術的難易度や未解決だけを、上位判断担当へ切り替える理由にしない。

## 指摘を扱う

重大な順に根拠と AC への影響を確認し、修正するか、直さない理由を記録する。
好みだけの変更を膨らませず、実際の不具合・不足経路を検証する。
修正後は影響する検査と push 前の必須検査を通し、新 head の必須 CI と独立レビューを確認する。
旧 SHA の承認を新 SHA へ自動流用しない。契約が限定 carryover を認める場合はその条件を確認する。

判定の受領・中継・外部投稿・status 反映は、未関与の担当と実際の権限に従う。
レビュー担当へ許可されていない投稿・approve・merge を行わせない。
未達や取得失敗を PASS にしない。指摘ゼロなら確認範囲と未確認範囲を示す。

他人の PR を読むだけの依頼では指摘を返す。外部コメント投稿はその依頼に含まれる場合だけ行う。
`concafe-techo` の最終判定・署名・中継・自動 Ready / guarded auto-merge は、対象タスクに適用される正本に従う。
