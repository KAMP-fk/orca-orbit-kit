# Orca の定期実行を管理する

定期実行の作成・変更・実行は、その依頼と委任がある場合だけ行う。
スキルの読込や監視用コマンドの追加だけで、外部の自動化を新設しない。

対象環境の `orca-cli` スキルを読み、実際に使う CLI が返す版対応の automation reference を使う。
過去の CLI の機能・flag を現在も同じと仮定しない。既存の自動化を確認して重複を避ける。

- repo の契約に合う precheck と対象 Issue / 担当の排他を使う。
- folder trust が必要な agent では、事前確認済みの固定 checkout を再利用する。
  新規 checkout を毎回作る必要がある場合は、起動・セットアップ・信頼の手順を具体化してから使う。
- モデル・effort・実行範囲・失敗時の動きを明示し、供給断で自動に provider を切り替えない。
- 変化・完了・失敗・ユーザー対応が必要な場合を通知の対象にする。定期の一律報告は依頼がある場合だけ。

スケジューラの completed 表示だけを、agent 起動や作業の完了と読まない。
対象 task / terminal の状態と出力、成果物、依頼の完了条件を確認する。
実行失敗は失敗として記録し、未確認の外部停止・設定変更・削除を完了扱いしない。
