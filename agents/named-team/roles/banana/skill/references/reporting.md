# 完了条件と記録

依頼された終点を [contracts.md](contracts.md) で確認する。
PR 作成・CI 緑・レビュー通過・merge は別の事実で、それぞれだけで Done としない。
merge 後の Preview 実証・運用確認・cleanup が AC に含まれるなら、その実結果まで追う。
権限がない条件は成功とせず、次の担当と具体的な行動を残す。依存しない作業は続ける。

## 完了を確認する

確認済みの項目には情報源・full SHA または対象識別子・観測時刻を付ける。
未達には必要な情報 / 操作・担当・次の行動を付ける。
外部反映は実際の投稿先や状態を読み直して確認する。
人間ゲートや独立レビューを、実装者の自己判定で代替しない。
最後に現 checkout の未保存変更・未 push commit・再利用する担当 / terminal を確認する。
cleanup は所有者と範囲を確認し、必要な作業を保全してから対象契約の手段で行う。

## 状況カード

Banana が `~/brain/dev/状況/<repo>.md` を置換する。他の担当に書かせない。
frontmatter と見出しを含め50行以内。初回は `_テンプレート.md` を使う。

- 解決した詰まり・完了した進行中の項目は消す。
- 現在の担当、Issue / PR / SHA、残件と次の行動を短く残す。
- 現物を確認した日時と情報源を示す。カードを読んだ時刻を検証時刻にしない。
- 注意は5行以内。理由と過去の経緯は decisions / knowledge に回す。
- 一行の現在地と最終更新を直す。

未達を消してカードだけ完了にしない。古いカードを外部状態の証拠にしない。

## 報告

Banana が `~/brain/dev/報告/YYYY-MM-DD.md` に追記する。過去を改変しない。
相棒は報告を読み、逆向きに Tomato の領域へ書かない。
`~/brain/README.md` の frontmatter (`date` / `project` / `tags`)・`[[wikilink]]`・
decisions 1件1ファイルの規約を使い、書いた変更を commit する。

以下は必要な項目だけ使う。実施していない見出しを埋めない。

```markdown
## 動かしたもの
- <repo> <issue / PR> … <full SHA / 結果の根拠 / 確認日時>

## 残っている条件
- <条件> … <必要な情報・操作> / 担当: <誰> / 次: <具体的な行動>

## 持ち主に返す判断
- <問い> … <止まっている理由 / 回答後に進む作業>
- Fable確認: <回答・推奨 / 根拠・確認時刻>
- 1. <推奨案・効果と代償> / 2. <他案・効果と代償> / 3. <必要なら他案>
- 推奨理由: <根拠と残る不確実性>

## 気づいたこと
- <後から効く事実と情報源>
```

できなかったことをできなかったと書く。外部未確認を解消したように報告しない。
