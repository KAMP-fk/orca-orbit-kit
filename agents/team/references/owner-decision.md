# Owner 判断待ちの確認手順

2026-10-03 JST の Owner 指示。Tomato または Orca が Owner の判断・承認・本人操作を
必要として止まった場合は、Fable に確認したうえで、推奨案付きの選択肢を Owner に提示する。
Fable の助言・推奨と、Owner の回答・承認を別の事実として記録する。

## Fable への確認

Fable は現在、相談窓口 Tomato の起動モデル。Tomato が材料と推奨を整理済みなら、
同じ確認のために別の Fable を起動しない。対象契約が別担当の判断を要求する場合はその経路を使う。
特に concafe の上位判断と最終 verdict は、現在の Owner が指定する別 Codex タスクの条件を維持する。

1. 現物で詰まりを確認し、何が未決か、止める操作、判断に依存せず続けられる作業を整理する。
   古い状況カードや「Owner待ち」の表記だけで判断待ちを確定しない。
2. 問いを一つに絞り、実行可能な選択肢・各案の利点と代償・一次資料の原文・
   既存の決定と決定者を揃える。[Fable の手順](/Users/kamp/orca/agents/team/roles/tomato/skill/references/fable.md) で一度に渡す。
3. Fable に、推奨する選択肢、推奨理由、他案との主要な違い、不確実な点を確認する。
   実際の対象契約と委任された連絡経路を使い、同じ問いを複数の Fable に送らない。
4. 依頼を送ったことと回答を受け取ったことを分け、Fable の応答・担当識別子・確認時刻を保持する。
   接続不能や材料不足を「Fable確認済み」にしない。その場合は不足と次の行動を Owner へ報告する。

Owner の回答を待つ間も、判断に依存しない調査・実装・検証は承認済みの範囲で続ける。
必要な本人操作、署名、CI、独立レビュー、人間ゲートを Fable の推奨で代替しない。

## Owner への選択肢

Fable の回答を受けたら、Tomato または Orca の一方が問いをまとめて提示する。
Owner が選んだ後に何が進むかまで具体化し、同じ確認を両役から重複して送らない。

- 実質的に異なる選択肢を通常2〜3個に絞る。提示する案は実行条件も含めて正確にする。
- **推奨案を先頭に置き、`推奨 / Recommended` と表示する。**推奨は通常一つ。
- 各案に効果と主な代償を短く添える。推奨理由と残る不確実性を示す。
- Fable の推奨内容と、提示担当の推薦が異なる場合は、その差と根拠を明示する。
- 使える環境では選択式の質問 UI を使い、自由記述でも答えられるようにする。
  選択 UI が使えなければ番号付きの選択肢で提示する。
- 本人操作だけで選択の余地が無い場合は、架空の代替案を作らず、実行するか保留するかと必要操作を示す。
- 推奨案の事前選択、無回答、経過時間を Owner の回答・承認と扱わない。

提示の形:

```text
確認したいこと: <Owner が決める一点>
止まっている理由: <確認済みの事実と、回答後に進む作業>
Fable確認: <応答の要点・推奨・確認時刻／未確認ならその理由>

1. <案A>（推奨 / Recommended）— <効果と主な代償>
2. <案B> — <効果と主な代償>
3. <案C> — <必要な場合だけ>

推奨理由: <判断を支える根拠と残る不確実性>
```

Owner の回答を受けたら、選んだ案・決定者・実行範囲を記録し、Orca の進行へ戻して再開する。
回答の対象外へ権限を広げず、再確認は前提・範囲・影響が変わった場合に行う。
