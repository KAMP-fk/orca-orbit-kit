# review-relay — `review:passed` を中継する専任

**仕事は1つだけ。**独立レビューの結果を確かめて、`review:passed` の commit status を付ける。

```
review-relay <PR番号> <レビュー記録のURL または ローカルファイル> --verdict <判定ファイル> [--repo <owner/name>] [--dry-run] [--correct-target-url]
```

`--correct-target-url` は、現在 head の最新 `review:passed` が success で、その `target_url` がこの PR の issue コメント URL の形でない場合の訂正だけに使う。新しい URL は `https://github.com/<repo>/pull/<PR番号>#issuecomment-<正の整数>` とし、記録本文は full SHA・CAF-308 の3行・判定の逐語を含む既存の門をすべて通し、モデルの判定も通常どおり受ける。status 履歴を全ページ読み、日時（同秒は id）で最新を選ぶ。履歴にこの PR の正しい形のコメント URL を指す success が一つでもあれば、同じ head の訂正を拒否する。フラグなしでは従来どおり二重投稿を拒否する。判定の上書きや別の判定の再投稿には使ってはいけない。訂正であることと旧 URL → 新 URL は `log/` に残る（機械の門での早期拒否は従来どおり記録しない）。

## なぜ専任が要るか

`docs/WORKFLOW.md` の中継規則（逐語）:

> 親は中継前に…自分が対象 PR の実装・修正・指摘対応に関与していないことを運用で確認する。
> 関与していた親は中継を担当しない。その場合は別の未関与のオーケストレーターが、
> いなければ持ち主が中継する。これは**人による運用上の確認であり、機械的な検証ではない**

**2026-10-01 に、2本連続で中継できる者がいなくなった。**

| | #290 | #289 |
|---|---|---|
| worker | 実装者 | 実装者 |
| Banana（dev オーケストレーター） | E2E を修正 | 衝突解決 |
| トマト | 修正を指示 | 受入条件3 の指摘対応 |
| **残るのは** | **持ち主** | **持ち主** |

**プールが小さく、作業に触れると抜けるので、必ず持ち主に落ちる。**

**この専任は、構造的にいつでも資格がある。**コードを書かない。指摘に答えない。issue を直さない。
**毎回まっさらなセッションで判定するので、前の PR の関与も持ち越さない。**

## 設計 —— 特権は script 側にある

**判定するモデルは read-only サンドボックスで、ネットワークも遮断されている**
（`~/.codex/review-relay.config.toml`）。**だからモデルは自分では POST できない。**

```
 launcher（特権あり）              モデル（read-only・ネットワーク遮断）
 ─────────────────────            ──────────────────────────────
 1. gh で事実を集める      ──→     事実シートだけを読む
 2. 機械の門を通す                 1行の判定を返す
 3. 判定を1行だけ受け取る  ←──     RELAY: POST / RELAY: REFUSE — 理由
 4. POST するのは script
```

**モデルが判定を偽っても、POST は script が1種類のリクエストしか打たない。**
**launcher は `RELAY: POST` の1行以外では何も実行しない。**

## 機械の門（fail-closed。1つでも欠けたらモデルを呼ばない）

| 門 | 落ちる理由 |
|---|---|
| **レビュー記録の本文が読めること** | **読めないものを中継しない** |
| **PR が Draft でないこと** | **Draft の中継はしない** |
| **`risk:high` / `risk:low` のどちらかが付いていること** | **ラベルの不在を低リスクの証拠にしない**（CAF-283 と同じ fail-closed） |
| **その head に `review:passed` success が未だ無いこと** | **二重に出さない** |
| **失敗している check が無いこと** | **緑でないものを中継しない** |
| **pending の check が無いこと** | **走り終わる前に中継しない** |
| **記録に head の full SHA が逐語で在ること** | **どの SHA を見たか書いていない記録を中継しない**（CAF-288 / ADR-062） |

## 判定の段がモデルに問うこと

1. **判定が PASS か**（CHANGES_REQUIRED / BLOCKED / 条件つき PASS はすべて不可）
2. **記録がその head SHA を対象にしているか**（別 SHA の流用は不可）
3. **レビュアーの未関与が記録に書かれているか**（書いていなければ不可。「たぶん」で通さない）
4. **未解決の High / Medium が無いか**（Low は行き先が書かれていれば可）
5. **check に失敗や未完了が無いか**

**推測で補わない。書いていないことは「無い」として扱う。**

## やらないこと

**merge / push / ファイル編集 / ラベル変更 / Draft 解除 / issue 更新。**

**`review:passed` を付けるだけ。**そのあと merge するのは `auto-merge.yml` のゲートであり、
**この専任は手動 merge をしない。**

## 監査記録

`log/YYYY-MM-DD.md` に追記する。PR 番号 / head SHA / 記録の URL / ラベル / 判定 / POST したか。

各エントリに `- launcher: parent=<親プロセスの comm> pid=<親 PID>` を1行残す。
起動時の `$PPID` と `ps -o comm= -p "$PPID"` を使い、コマンド引数や環境変数は収集しない。
`comm` は Bash の `%q` でエスケープするので、改行などが含まれても1行に収まる。
`ps` の失敗・空・空白だけの出力は `parent=取得できなかった` と理由を明記し、PID は残す。
取得失敗は門や中継の結果を変えない。起動者の値はモデルに渡さず、独立性の判定にも使わない。
親プロセス名と PID は後から追跡する手掛かりであり、エージェント名や Codex セッションの一意な証明ではない。

**モデルが REFUSE を返したときも記録する。**「中継しなかった」ことが後から追える。
機械の門での早期拒否や判定を読み取れない場合は、現行どおり監査エントリを作らない。
